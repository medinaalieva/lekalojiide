## 1. Введение и цели аудита

Цель аудита информационной безопасности и целостности данных — подтвердить, что платформа **LEKALO ZHIIDE** защищена от подделки цен, несанкционированного скачивания цифровых выкроек, покупки пустых/поврежденных файлов и утечки конфиденциальной информации.

Аудит проводился методами сквозного тестирования API, инспекции исходного кода backend-микросервисов, прямых валидаций на уровне базы данных PostgreSQL и эмуляции атак со стороны непривилегированного пользователя.

## 3. Детальные результаты проверок

### 3.1. Purchase Guard: Защита от покупки вариантов без файлов
* **Механизм защиты:** При вызове метода добавления товара в корзину `CartService.addItem()` выполняется пре-валидация сущности `ProductVariant`:
  ```typescript
  if (!variant.fileKey || variant.fileSize === null || variant.fileSize === 0) {
    throw new BadRequestException("Выкройка недоступна для скачивания (отсутствует цифровой файл)");
  }
  ```
* **Тестовый сценарий:** Попытка добавить синтетический вариант `T527_VAR_NOFILE` (`fileKey: null`).
* **Результат:** Запрос отклонен со статусом **HTTP 400 Bad Request**. В корзину не поступило ни одной невалидной позиции.

### 3.2. Purchase Guard: Блокировка файлов-заглушек (< 1024 байт)
* **Механизм защиты:** Полноценный PDF-файл выкройки не может весить менее 1 килобайта. Любые stub-файлы (пустые текстовые файлы с расширением `.pdf` или поврежденные дампы) блокируются:
  ```typescript
  if (variant.fileSize < 1024) {
    throw new BadRequestException("Цифровой файл выкройки поврежден или не загружен полностью");
  }
  ```
* **Тестовый сценарий:** Создан вариант с файлом размером 128 байт. Отправлен запрос на добавление в корзину.
* **Результат:** Запрос немедленно отклонен со статусом **HTTP 400**. Покупка бракованных/тестовых файлов невозможна.

### 3.3. Inactive Variant Guard: Блокировка отключенных вариантов
* **Механизм защиты:** Продажа закрытых позиций (`isAvailable: false`) блокируется на двух уровнях:
  1. Публичный каталог не отдает кнопки покупки для вариантов с `isAvailable: false`.
  2. Backend `CartService` и `OrderService` повторно запрашивают актуальный статус из базы данных.
* **Тестовый сценарий:** Товар «Пальто оверсайз Чолпон» имеет 6 вариантов с флагом `isAvailable: false`. Отправлен прямой API-запрос на покупку варианта `cholpon-42-164-a4`.
* **Результат:** Сервер вернул **HTTP 400 Bad Request**. Продажи эталонного каталога надежно заблокированы до боевой загрузки чистовых файлов.

### 3.4. Server-Side Pricing Authority: Защита от подделки цен
* **Механизм защиты:** Клиентское приложение **не передает** цену при формировании заказа. В теле запроса `POST /api/v1/orders` передаются исключительно идентификаторы вариантов и формат:
  ```typescript
  // Клиентский payload
  { items: [{ variantId: "...", format: "A4" }] }
  ```
* **Бизнес-логика бэкенда:**
  - Цена извлекается из таблицы `ProductVariant` или берется базовая цена `Product.price`.
  - Применяется дифференциальная наценка формата из `ProductVariant.priceOverride` или `PatternFormat.priceModifier`.
  - Проверяются активные скидки в `DiscountSchedule` (`startsAt <= now <= endsAt`).
  - При покупке бандла применяется процентная скидка `bundleDiscountPercent`.
* **Результат:** Попытка внедрения произвольной стоимости в JSON-запрос полностью игнорируется бэкендом.

### 3.5. Order Immutability: Неизменяемость оплаченного заказа
* **Механизм защиты:** При переходе заказа в статус `PAID`:
  1. Создается снимок цен и наименований в записях `OrderItem` (`priceAtPurchase`).
  2. Заказ блокируется от мутаций.
  3. Последующие изменения цен администратором в каталоге не влияют на суммы уже совершенных сделок.
* **Результат:** Подтверждена целостность финансовых транзакций и бухгалтерской отчетности.

### 3.6. Entitlement Isolation: Защита от IDOR (Insecure Direct Object Reference)
* **Механизм защиты:** Эндпоинт генерации ссылок на скачивание `GET /api/v1/cabinet/downloads/:entitlementId` проверяет принадлежность права текущему авторизованному пользователю:
  ```typescript
  const entitlement = await prisma.purchaseEntitlement.findUnique({ where: { id } });
  if (!entitlement || entitlement.userId !== currentUser.id) {
    throw new ForbiddenException("У вас нет прав на скачивание данного файла");
  }
  ```
* **Тестовый сценарий:**
  - Покупатель A (`T527_buyer_a@example.com`) приобрел выкройку и получил `entitlementId`.
  - Покупатель B (`T527_buyer_b@example.com`) авторизовался и попытался вызвать API скачивания по `entitlementId` Покупателя A.
* **Результат:** Сервер вернул **HTTP 403 Forbidden**. Чужие выкройки недоступны.

### 3.7. Ephemeral Signed URLs: Безопасная выдача файлов через S3
* **Механизм защиты:** Файлы выкроек хранятся в защищенном приватном бакете S3 (Supabase Storage / MinIO). Прямой публичный доступ к бакету закрыт.
* **Генерация ссылок:** По запросу пользователя создается временная ссылка с криптографической HMAC-подписью и сроком жизни (TTL):
  - Срок действия: 15 минут (900 секунд).
  - Ссылка жестко привязана к ключу объекта.
  - По истечении TTL ссылка становится недействительной.
* **Результат:** Исключена утечка ссылок в открытый интернет и массовый парсинг платных материалов.

### 3.8. ALL Bundle Integrity: Целостность покупки размерного ряда
* **Механизм защиты:** При покупке пакета «Все размеры» сервис `OrderService` генерирует права доступа (`PurchaseEntitlement`) для всех вариантов выбранной ростовки и формата:
  ```typescript
  const variants = await prisma.productVariant.findMany({
    where: { productId, height: targetHeight, format: targetFormat, isAvailable: true }
  });
  ```
* **Результат:** Покупатель гарантированно получает доступ ко всей сетке размеров без «выпадения» отдельных лекал.

### 3.9. Database Isolation: Изоляция тестовой базы данных
* **Проверка:**
  ```sql
  SELECT current_database(); -- lekalo_test
  ```
* **Результат:** 100% операций выполнялись в изолированной тестовой ветке Neon PostgreSQL. Продакшн-база и сторонние серверы не затрагивались.

### 3.10. Аутентификация, токены и защита секретов
* **Хеширование паролей:** Использован алгоритм `bcrypt` с фактором стоимости 10. Открытые пароли в БД не сохраняются.
* **Авторизация:** JWT-токены с алгоритмом HS256, валидацией срока жизни (`exp`) и структуры пользователя.
* **Защита секретов:** Ни один секретный ключ (`JWT_SECRET`, `DATABASE_URL`, `S3_SECRET_KEY`) не попал в логи тестов или публичные ответы API.
