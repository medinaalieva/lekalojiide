## 2. Архитектура и доказательства устранения дублирующего запроса

### 2.1. Серверная дедупликация (Next.js Request Deduplication)
В `page.tsx` обе функции — `generateMetadata` и `ProductPage` — обращаются к единой функции `getProduct(slug)`, выполняющей:
```typescript
fetch(`${baseUrl}/api/v1/catalog/products/${slug}`, {
  next: { revalidate: 60 },
});
```
Next.js кэширует вызовы `fetch` с идентичным URL и параметрами в пределах одного цикла рендеринга.
- **Входящие запросы к NestJS API при открытии `/catalog/palto-oversayz-cholpon`:**
  - `generateMetadata`: выполняет `fetch`.
  - `ProductPage`: обращается к результату из кэша первого вызова.
  - **Фактическое количество запросов к бэкенду:** **строго 1** (вместо 2 на сервере).

### 2.2. Ликвидация повторного запроса после гидратации (Client Hydration)
В `ProductDetailView.tsx`:
```typescript
useEffect(() => {
  // 1. Если initialProduct передан сервером и соответствует текущему slug — НЕ делать повторный запрос!
  if (initialProduct && initialProduct.slug === slug) {
    if (initialProduct.category?.slug && similarProducts.length === 0) {
      fetchSimilar(initialProduct.category.slug, initialProduct.id);
    }
    return;
  }
  // 2. Если передан initialError, не спамить API
  if (initialError) return;

  // 3. Fallback: только при отсутствии данных с сервера
  loadProduct();
}, [slug, initialProduct, initialError]);
```
- **Запросы к API товара после гидратации в браузере:** **0** (повторный запрос полностью ликвидирован).
- **Фоновый запрос похожих товаров:** выполняется асинхронно через `fetchSimilar` внизу страницы, не блокируя первый экран.

### 3.6. Проверка обработки временных ошибок API (5xx / Network Error)
При временном сбое API бэкенда или сетевой недоступности:
- `getProduct` возвращает `{ kind: "error", error: "..." }`.
- `ProductPage` передаёт `initialError` в `ProductDetailView`.
- Пользователю отображается статус **«Временная ошибка сервера»** с реальным текстом ошибки и кнопкой **«Обновить страницу»** (reload).
- Сообщение «Выкройка не найдена» **НЕ отображается**, что исключает дезинформацию покупателя.

### 3.7. Сохранение функциональности корзины и вариантов
- Выбор размера (например, 42, 44, 46), ростовки (164-170) и формата печати (A4, плоттер) синхронизируется через `useState` и `useMemo`.
- Переключение режима «Один размер» / «Комплект ALL» динамически пересчитывает цену.
- Обработчик `handleAddToCart` передаёт `activeVariant.variantId` в `useCart().addItem(...)` с сохранением валидации дубликатов `VARIANT_ALREADY_IN_CART` и тостов.
