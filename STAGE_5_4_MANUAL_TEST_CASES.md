### TC-01: Успешная первичная загрузка валидного PDF (Happy Path)
- **Цель:** Проверить полный цикл первичной загрузки выкройки на свободный SKU.
- **Предусловия:** Авторизован администратор (`admin@lekalozhiide.local`). Открыта страница `/admin/products/[id]/files`. Выбран вариант без файла (`⚠️ Файл отсутствует`).
- **Шаги выполнения:**
  1. Нажать «Загрузить PDF» в строке варианта 42 размера.
  2. Выбрать валидный PDF-файл (`palto-oversayz-cholpon-42-164-170-A4.pdf`, размер 2.4 МБ).
  3. Ввести комментарий: *«Первичный релиз лекала»*.
  4. Нажать «Сохранить в хранилище».
- **Ожидаемый результат:**
  - Зеленое уведомление об успешной загрузке.
  - В таблице появляется отметка `✓ v1 (2400 КБ)`.
  - В БД создана запись `FileVersion` с `versionNumber = 1` и sha256.
  - В строке появляется кнопка «Тест ссылки».

### TC-02: Попытка загрузки файла с неверным расширением (.exe, .docx, .zip)
- **Цель:** Убедиться, что интерфейс и API отклоняют файлы недопустимых типов.
- **Шаги выполнения:**
  1. Нажать «Загрузить PDF».
  2. В системном диалоге выбора файлов переключить фильтр на «Все файлы» и выбрать `malicious.exe` или `archive.zip`.
- **Ожидаемый результат:**
  - Появляется сообщение об ошибке: *«Разрешены только файлы формата PDF (.pdf)»*.
  - Кнопка «Сохранить» заблокирована, отправка на сервер не происходит.
  - При прямой отправке через cURL/Postman с `contentType: application/zip` сервер возвращает HTTP 400 `INVALID_MIME_TYPE`.

---

### TC-03: Загрузка файла с неверной сигнатурой (MIME spoofing, нет `%PDF-`)
- **Цель:** Проверить реакцию сервера на файл с расширением `.pdf`, содержащий вредоносный HTML или текст.
- **Шаги выполнения:**
  1. Создать текстовый файл с содержимым `<html><script>alert(1)</script></html>` и переименовать в `test_exploit.pdf`.
  2. Отправить его через модальное окно с `contentType: application/pdf`.
- **Фактический результат в текущей системе:**
  - ⚠️ **УЯЗВИМОСТЬ (G-01):** Сервер принимает файл и сохраняет его в бакет, так как проверяет только строку `contentType`, не анализируя байты заголовка!
- **Ожидаемый результат после устранения дефицита G-01:**
  - Сервер анализирует буфер, не находит байты `0x25 0x50 0x44 0x46` (`%PDF`) и возвращает HTTP 400 `CORRUPTED_OR_INVALID_PDF`.

### TC-04: Попытка загрузки файла размером свыше 30 МБ
- **Цель:** Проверить принудительное отсечение тяжелых неоптимизированных файлов.
- **Шаги выполнения:**
  1. Подготовить файл размером 35 МБ (например, неотсканированный скан высокого разрешения).
  2. Попытаться выбрать файл в модальном окне.
- **Ожидаемый результат:**
  - На клиенте всплывает ошибка: *«Размер файла не должен превышать 30 МБ»*.
  - При попытке обойти клиентскую валидацию бэкенд возвращает HTTP 400 `FILE_TOO_LARGE`.

### TC-05: Загрузка файла с неверным именем SKU (человеческий фактор)
- **Цель:** Проверить защиту от случайной привязки чужого размера.
- **Шаги выполнения:**
  1. В таблице нажать «Загрузить PDF» в строке **Размера 42**.
  2. Выбрать файл **Размера 48** (`palto-oversayz-cholpon-48-164-170-A4.pdf`).
- **Фактический результат в текущей системе:**
  - ⚠️ **ДЕФИЦИТ (G-02):** Система успешно привязывает файл 48 размера к SKU 42 размера.
- **Ожидаемый результат после устранения дефицита G-02:**
  - Появление предупреждающего модального окна: *«Внимание: выбранный файл содержит маркер '48', тогда как вы загружаете его для размера '42'. Подтвердите действие или выберите верный файл»*.

### TC-06: Повторная загрузка и инкремент версии (v1 $\rightarrow$ v2)
- **Цель:** Проверить корректность механизма версионирования при замене лекала.
- **Шаги выполнения:**
  1. В строке с уже загруженной выкройкой (статус `✓ v1`) нажать **«Заменить PDF»**.
  2. Выбрать исправленный файл лекала.
  3. Ввести в поле changelog: *«v2: Скорректирована линия проймы»*.
  4. Нажать «Сохранить в хранилище».
- **Ожидаемый результат:**
  - Статус в строке обновляется на `✓ v2`.
  - Версия `v1` сохраняется в БД со своим неизменным SHA-256 хешем и старым файлом в S3.
  - Покупатели при скачивании начинают автоматически получать версию `v2`.

---

### TC-07: Удаление версии файла и откат текущей версии
- **Цель:** Проверить корректность удаления конкретной версии файла и переназначения активной версии.
- **Шаги выполнения:**
  1. Для варианта с версиями v1 и v2 нажать иконку корзины («Удалить версию файла») для версии v2.
  2. Подтвердить удаление в диалоге браузера.
- **Ожидаемый результат:**
  - Отправляется запрос `DELETE /api/v1/admin/storage/variants/:id/files/:versionId`.
  - Файл версии v2 физически удаляется из S3-бакета.
  - Запись v2 удаляется из таблицы `file_versions`.
  - Поле `DigitalFile.currentVersionId` автоматически переключается назад на версию `v1`.
  - Статус варианта в таблице возвращается к `✓ v1`.

### TC-08: Попытка несанкционированной загрузки без прав ADMIN
- **Цель:** Проверить надежность ограничения доступа к эндпоинтам управления файлами.
- **Шаги выполнения:**
  1. Выполнить запрос `POST /api/v1/admin/storage/upload-pattern` без передачи заголовка `Authorization`.
  2. Повторить запрос с JWT-токеном обычного покупателя (`role: USER`).
- **Ожидаемый результат:**
  - Запрос без токена: возвращает HTTP 401 `UNAUTHORIZED`.
  - Запрос с токеном USER: возвращает HTTP 403 `FORBIDDEN` («Недостаточно прав для выполнения действия»).
  - Никаких изменений в базе данных и хранилище не происходит.

### TC-09: Проверка приватности файла и срока жизни временной ссылки
- **Цель:** Убедиться, что файлы лекал закрыты от прямого несанкционированного скачивания.
- **Шаги выполнения:**
  1. Получить S3-ключ файла из базы (например: `patterns/.../file.pdf`).
  2. Попытаться открыть прямой публичный URL вида `https://[supabase-project].storage.supabase.co/storage/v1/object/public/pattern-files/...`.
  3. Нажать кнопку «Тест ссылки» в админ-панели и получить временный Presigned URL.
  4. Проверить скачивание сразу.
  5. Повторить попытку скачивания по этой же ссылке через 11 минут (после истечения TTL 600 секунд).
- **Ожидаемый результат:**
  - Прямой URL: возвращает ошибку доступа `403 Forbidden` / `NoSuchKey` (бакет полностью приватный).
  - Свежий Presigned URL: файл успешно скачивается.
  - Просроченный Presigned URL: S3 возвращает ошибку `Request has expired`.
