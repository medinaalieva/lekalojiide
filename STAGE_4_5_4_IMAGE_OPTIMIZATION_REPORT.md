## 4. Особенности кэширования Supabase Storage

> **Ограничение Supabase Storage:**
> При отдаче файлов из публичного бакета Supabase Storage возвращает заголовок:
> `Cache-Control: no-cache` (или `private, no-cache`).
>
> **Поведение Next.js Optimizer:**
> Оптимизатор Next.js учитывает upstream-заголовки кэширования. Для изображений с `images.unsplash.com` он выставляет заголовок `Cache-Control: public, max-age=31536000, must-revalidate`. Для изображений Supabase Storage он транслирует короткий TTL: `Cache-Control: public, max-age=60, must-revalidate`.
>
> **Компенсирующий фактор:**
> Сервер Next.js кэширует сгенерированные WebP/AVIF файлы на локальном диске (`frontend/.next/cache/images`). Повторные запросы на один и тот же размер отдаются за **3–9 мс** без повторного скачивания из Supabase и без повторного кодирования через sharp.
>
> В соответствии с требованиями задачи, конфигурация Supabase Storage оставлена без изменений.

## 5. Защита от бесконечного цикла ошибок (`onError`)

В компоненте `ProductCard.tsx` реализована безопасная логика:
1. Состояние ошибки отслеживается через React state: `const [imgError, setImgError] = useState(false)`.
2. Если `coverImageUrl` отсутствует ИЛИ `imgError === true`, компонент `<Image />` полностью демонтируется из DOM.
3. Вместо него рендерится чистый SVG-компонент библиотеки `lucide-react`:
   ```tsx
   <div className="flex flex-col items-center justify-center p-6 text-atelier-muted bg-gradient-to-b from-brand-50/40 to-atelier-subtle w-full h-full">
     <div className="w-12 h-12 rounded-full bg-brand-100/60 flex items-center justify-center mb-2">
       <Scissors className="w-6 h-6 stroke-[1.4] text-brand-800" />
     </div>
     <span className="text-[11px] tracking-wider uppercase text-center font-medium text-atelier-muted">
       Цифровая выкройка
     </span>
   </div>
   ```
4. Поскольку в заглушке отсутствует тег `<img src="...">`, событие ошибки физически не может сработать повторно. Бесконечный цикл ошибок исключён на 100%.
