## 1. Обзор выполненной работы

В рамках задачи **TASK-006** полностью реализован backend-модуль каталога цифровых выкроек интернет-магазина **LEKALO ZHIIDE**.

Реализация строго соответствует архитектурной спецификации (`docs/architecture/ARCHITECTURE.md`), схеме базы данных (`prisma/schema.prisma`, `docs/architecture/DATABASE_SCHEMA.md`) и API-спецификации (`docs/architecture/API_SPECIFICATION.md`).

### Ключевые возможности:
1. **Публичный каталог (`CatalogController` / `/api/v1/catalog/*`)**:
   - Дерево категорий любой вложенности (`GET /categories`) с иерархией `children`, сортировкой по `displayOrder` и фильтрацией только активных узлов.
   - Справочник доступных фильтров (`GET /filters`) с получением размеров (RUS/INT), ростовок (см), форматов печати (A4, Плоттер 900мм) и уровней сложности пошива напрямую из базы данных.
   - Фильтрация и поиск товаров (`GET /products`):
     - Фильтрация по категории с автоматическим включением всех дочерних подкатегорий.
     - Мульти-фильтры по размерам, ростам, форматам печати и уровням сложности.
     - Полнотекстовый поиск (`search`) по названию и описанию модели.
     - Сортировка (`newest`, `price_asc`, `price_desc`, `title_asc`).
     - Пагинация с защитой от перегрузок (`limit` от 1 до 50, по умолчанию 12).
     - Строгая фильтрация черновиков: неопубликованные товары (`isActive = false`) скрыты от публики.
   - Детальная страница выкройки (`GET /products/:slug`):
     - Базовая цена в сомах (`KGS`).
     - Полная галерея изображений, упорядоченная по `displayOrder` и обложке `isCover`.
     - Матрица активных вариантов (доступные сочетания размер + рост + формат).
     - Наличие инструкции в виде булева флага `hasInstruction: boolean` **без раскрытия приватных S3-ключей или путей хранилища**.
   - Доступные варианты выкройки (`GET /products/:id/variants`): подробный список вариантов с артикулами (SKU), ценами и статусом наличия.

2. **Административное управление каталогом (`CatalogAdminController` / `/api/v1/admin/*`)**:
   - Авторизация и безопасность:
     - Защита через RBAC: доступ строго ограничен ролями `ADMIN` и `CONTENT_MANAGER`. Попытка доступа без токена возвращает `401 Unauthorized`, от покупателя (`CUSTOMER`) — `403 Forbidden`.
     - Проверка доверенного источника запросов (`Origin` / CSRF) для предотвращения межсайтовых атак.
   - Управление категориями:
     - Создание (`POST /categories`) и редактирование (`PUT /categories/:id`).
     - Автогенерация slug с поддержкой кириллицы и кыргызских букв.
     - Поддержка вложенности категорий через `parentId`.
   - Управление товарами:
     - Создание (`POST /products`) и редактирование (`PUT /products/:id`).
     - Публикация/снятие с публикации (`PATCH /products/:id/status`).
   - Пакетный генератор матрицы вариантов (`POST /products/:id/variants/batch`):
     - Формирование декартова произведения: $\text{размеры} \times \text{ростовки} \times \text{форматы}$.
     - Автоматическая генерация уникальных SKU по шаблону `[PREFIX]-[SIZE]-[HEIGHT]-[FORMAT]`.
     - Идемпотентность и атомарность через `upsert` с составным уникальным ключом `(productId, sizeId, heightId, formatId)`.
   - Управление галереей изображений:
     - Добавление фотографий (`POST /products/:id/images`) с установкой обложки и порядка отображения.
     - Удаление фотографий (`DELETE /products/:id/images/:imageId`).

3. **Локализация и кыргызская специфика**:
   - В утилите `slugify` реализована полная транслитерация кириллицы с нативной поддержкой кыргызских букв: `ө` -> `o`, `ү` -> `u`, `ң` -> `n` (например, «Көйнөк үлгүсү» -> `koynok-ulgusu`).
   - Базовая валюта — `KGS` (кыргызский сом), домен — `lekalo-zhiide.kg`.

## 3. Спецификация API каталога

### 3.1. Публичный API (`/api/v1/catalog`)

| Метод | Путь | Описание | Доступ |
|---|---|---|---|
| `GET` | `/api/v1/catalog/categories` | Иерархическое дерево активных категорий | Публичный |
| `GET` | `/api/v1/catalog/filters` | Справочные данные для фильтров (размеры, ростовки, форматы, сложность) | Публичный |
| `GET` | `/api/v1/catalog/products` | Пагинированный список опубликованных товаров с фильтрацией и поиском | Публичный |
| `GET` | `/api/v1/catalog/products/:slug` | Карточка товара по слагу (галерея, матрица вариантов, базовая цена) | Публичный |
| `GET` | `/api/v1/catalog/products/:id/variants` | Список активных вариантов товара | Публичный |

#### Параметры запроса `GET /api/v1/catalog/products`:
- `page` (number, default: 1) — номер страницы.
- `limit` (number, min: 1, max: 50, default: 12) — размер страницы.
- `categoryId` / `categorySlug` (string) — фильтр по категории (включая все дочерние подкатегории).
- `sizes` (string, comma-separated, e.g. `42,44,46`) — фильтр по размерам.
- `heights` (string, comma-separated, e.g. `164,170`) — фильтр по ростовкам.
- `formats` (string, comma-separated, e.g. `A4,PLOTTER_900`) — фильтр по форматам печати.
- `difficulty` (string, comma-separated, e.g. `BEGINNER,INTERMEDIATE`) — сложность пошива.
- `search` (string) — текстовый поиск по названию и описанию.
- `sort` (`newest` | `price_asc` | `price_desc` | `title_asc`, default: `newest`) — порядок сортировки.

### 3.2. Административный API (`/api/v1/admin`)
*Требует заголовок `Authorization: Bearer <token>` и роль `ADMIN` или `CONTENT_MANAGER`.*

| Метод | Путь | Описание | Доступ |
|---|---|---|---|
| `POST` | `/api/v1/admin/categories` | Создание категории | Admin / Content Mgr |
| `PUT` | `/api/v1/admin/categories/:id` | Редактирование категории | Admin / Content Mgr |
| `POST` | `/api/v1/admin/products` | Создание выкройки | Admin / Content Mgr |
| `PUT` | `/api/v1/admin/products/:id` | Редактирование параметров выкройки | Admin / Content Mgr |
| `PATCH` | `/api/v1/admin/products/:id/status` | Переключение публикации (`isActive`) | Admin / Content Mgr |
| `POST` | `/api/v1/admin/products/:id/variants/batch` | Пакетная генерация матрицы вариантов | Admin / Content Mgr |
| `POST` | `/api/v1/admin/products/:id/images` | Добавление изображения в галерею | Admin / Content Mgr |
| `DELETE` | `/api/v1/admin/products/:id/images/:imageId` | Удаление изображения из галереи | Admin / Content Mgr |

## 4. Безопасность и архитектурные решения

1. **Защита закрытых данных S3-хранилища**:
   - Модель `ProductInstruction` хранит системные параметры S3 (`s3Bucket`, `s3Key`, `checksumSha256`).
   - В публичных методах `CatalogService.getProductBySlug` закрытые ключи и имена bucket **никогда не возвращаются**. Клиенту передается исключительно флаг `hasInstruction: boolean`.
   - Загрузка самих файлов инструкций и лекал будет производиться через защищенные подписанные ссылки (Presigned URL) только после оплаты в соответствующих модулях.

2. **RBAC & CSRF Origin Guard**:
   - Контроллер `CatalogAdminController` централизованно проверяет роль инициатора запроса с использованием `extractAuthUser` и `checkRolePermissions`.
   - Попытка выполнить административное действие обычным клиентом (`CUSTOMER`) или неавторизованным пользователем мгновенно пресекается (HTTP 403 / 401).
   - Для мутирующих административных запросов проверяется заголовок `Origin`, сопоставляемый с белым списком разрешенных доменов (`http.config.ts`).

3. **Целостность данных и атомарная генерация SKU**:
   - При пакетной генерации вариантов выкроек используется `prisma.$transaction`.
   - Составной уникальный индекс `@@unique([productId, sizeId, heightId, formatId])` защищает от гонок данных и дубликатов.
   - Механизм `upsert` позволяет безопасно повторно вызывать генератор с новыми параметрами цен (`priceOverride`) без нарушения существующих связей.

4. **Защита от DoS на уровне базы данных**:
   - Лимит пагинации жестко ограничен значением `max(50)` в схеме Zod `CatalogQuerySchema`.
   - При фильтрации по дереву категорий рекурсивный сбор дочерних ID выполняется оптимизированным обходом в глубину (DFS) с ограничением на циклы.
