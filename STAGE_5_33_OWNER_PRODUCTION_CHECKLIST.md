## 2. Пошаговый регламент развёртывания (10 шагов)

### Шаг 1: Развёртывание чистой Production Neon PostgreSQL
1. Создать отдельный изолированный Production-проект в консоли [Neon.tech](https://neon.tech) (название: `lekalo-production-db`).
2. Скопировать защищённую строку подключения с SSL:
   ```env
   DATABASE_URL="postgresql://<prod_user>:<prod_password>@ep-<endpoint>.eu-central-1.aws.neon.tech/lekalo_prod?sslmode=require"
   ```
3. Выполнить накат миграций **строго через команду deploy** (категорически запрещено использовать `db push` или `migrate reset`, чтобы не повредить схему):
   ```bash
   npx prisma migrate deploy
   ```
4. Убедиться, что миграции применились без ошибок, а таблицы `products`, `product_variants`, `orders`, `payments`, `dictionaries` созданы в чистом виде без тестового мусора.

---

### Шаг 2: Настройка безопасного хранилища Supabase Storage
1. В консоли Supabase создать новый проект `LEKALO-ZHIIDE-PRODUCTION`.
2. Создать бакет для PDF-файлов выкроек:
   - **Имя бакета**: строго `patterns`
   - **Public bucket**: `ВЫКЛЮЧЕНО (False / Private)`
3. Настроить Row Level Security (RLS) политики:
   - Прямой анонимный доступ по публичным URL заблокирован.
   - Скачивание файлов возможно **только через подписанные временные ссылки (Signed URLs)** с временем жизни 15 минут (900 секунд).
4. Создать публичный бакет `images` для обложек и фотографий галереи (`Public bucket: ON`).
5. Скопировать боевые ключи:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (секретный ключ бэкенда для генерации signed URL).

---

### Шаг 3: Боевой домен и SSL-сертификат
1. Зарегистрировать домен `lekalojiide.com` (или национальный домен `lekalojiide.kg`).
2. В панели DNS-провайдера настроить записи:
   - `A`-запись `@` $\to$ IP-адрес Vercel (`76.76.21.21`);
   - `CNAME`-запись `www` $\to$ `cname.vercel-dns.com`.
3. В панели Vercel добавить домен `lekalojiide.com` и дождаться автоматической генерации бесплатного SSL-сертификата Let's Encrypt.
4. Проверить автоматический редирект с `http://` на `https://`.

---

### Шаг 4: Конфигурация переменных окружения Vercel
В панели проекта Vercel (`Settings -> Environment Variables`) заполнить следующие параметры для среды **Production**:

| Переменная | Описание | Пример значения |
| :--- | :--- | :--- |
| `DATABASE_URL` | Строка подключения к боевой Neon DB | `postgresql://...` |
| `NEXTAUTH_URL` | Канонический URL платформы | `https://lekalojiide.com` |
| `NEXTAUTH_SECRET` | Криптографический ключ сессий (64 hex) | `openssl rand -hex 32` |
| `NEXT_PUBLIC_APP_URL` | Публичный адрес сайта | `https://lekalojiide.com` |
| `SUPABASE_URL` | Адрес инстанса Supabase | `https://xyz.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Секретный ключ хранилища | Секретный токен |
| `SMTP_HOST` | Почтовый сервер | `smtp.resend.com` / `smtp.yandex.ru` |
| `SMTP_PORT` | Порт почты | `465` (SSL) или `587` (TLS) |
| `SMTP_USER` | Логин почты | `noreply@lekalojiide.com` |
| `SMTP_PASSWORD` | Пароль приложения / API-токен | Секретный пароль |
| `SMTP_FROM` | Имя отправителя | `LEKALO ZHIIDE <noreply@lekalojiide.com>` |
| `PAYMENT_GATEWAY_MODE` | Режим платёжного шлюза | `live` (или `mock` на этапе проверки) |
| `BANK_MERCHANT_ID` | Идентификатор мерчанта в банке | Выдаётся банком |
| `BANK_SECRET_KEY` | Секретный ключ подписи вебхуков | Выдаётся банком |
| `BANK_WEBHOOK_URL` | URL приёма уведомлений от банка | `https://lekalojiide.com/api/payments/webhook` |

### Шаг 5: Подключение транзакционного SMTP-шлюза
1. Выбрать надёжного провайдера транзакционной почты (Resend, SendGrid, Yandex 360 для бизнеса или Mailgun).
2. Подтвердить владение доменом `lekalojiide.com` через добавление DNS-записей:
   - `SPF`-запись: `v=spf1 include:... ~all`
   - `DKIM`-запись: цифровая подпись почтовых писем (предотвращает попадание в Спам)
   - `DMARC`-запись: `v=DMARC1; p=quarantine;`
3. Отправить тестовое письмо на внешние ящики (Gmail, Mail.ru) и убедиться в 100% доставке и корректном отображении фирменного оформления LEKALO ZHIIDE.

---

### Шаг 6: Договор интернет-эквайринга с банком
1. Заключить договор интернет-эквайринга (Демир Банк / Оптима Банк / MBank / O!Dengi / PayBox / FreedomPay).
2. Зарегистрировать в личном кабинете банка технические адреса:
   - **Success URL**: `https://lekalojiide.com/checkout/success?orderId={ORDER_ID}`
   - **Fail URL**: `https://lekalojiide.com/checkout/fail?orderId={ORDER_ID}`
   - **Callback / Webhook URL**: `https://lekalojiide.com/api/payments/webhook`
3. Получить боевой `Merchant ID` и криптографический секретный ключ (`Secret HMAC Key`).

---

### Шаг 7: Тестовый платёж на 1 сом (Банковский Smoke Test)
1. Выставить на витрине скрытый или тестовый товар стоимостью 1 сом (1 KGS).
2. Выполнить оплату с реальной банковской карты (Visa / Elkart / MasterCard).
3. Проверить прохождение банковского шлюза:
   - Происходит 3D-Secure подтверждение через SMS/Push банка;
   - Банковский сервер отправляет POST-уведомление на Webhook платформы;
   - Статус платежа в БД меняется на `COMPLETED`, статус заказа — на `PAID`;
   - Списание 1 сома отражено в банковской выписке.

---

### Шаг 8: Юридические документы и политика возврата
1. Разместить в подвале сайта (Footer) и на этапе оформления заказа обязательные юридические страницы:
   - **Публичная оферта на оказание услуг и продажу цифрового контента** (согласно законодательству Кыргызской Республики);
   - **Политика конфиденциальности и обработки персональных данных**;
   - **Правила возврата средств за цифровые товары**:
     > *«В соответствии с законодательством о защите прав потребителей, возврат денежных средств за электронные выкройки надлежащего качества после предоставления доступа к скачиванию файлов не осуществляется. В случае выявления конструктивного брака файла покупателю предоставляется исправленная версия либо производится возврат средств по заявлению»*.
   - **Реквизиты продавца**: ИП/ОсОО, ИНН, юридический адрес, телефон поддержки, контактный email.
2. Проверить наличие обязательного чекбокса *«Я согласен с условиями Публичной оферты»* перед переходом к оплате.

### Шаг 9: Сквозной тест «Покупка $\to$ Оплата $\to$ Email $\to$ Скачивание»
Провести комплексный контрольный цикл покупки реальным пользователем:
- [ ] Пользователь оформляет заказ на модель (например, пальто «Чолпон», р-р 44, плоттер);
- [ ] Оплачивает картой;
- [ ] Мгновенно перенаправляется на страницу подтверждения с активными кнопками скачивания;
- [ ] Получает на email письмо с чеком, номером заказа и прямыми ссылками;
- [ ] В личном кабинете в разделе «Мои выкройки» появляется купленная позиция;
- [ ] При клике на «Скачать A4» и «Скачать Plotter» файлы успешно сохраняются на устройство и открываются в PDF-ридере;
- [ ] При попытке заново зайти на страницу купленного пальто срабатывает **Purchase Guard** (кнопка заменена на «Уже приобретено»).

### Шаг 10: Финальное переключение и официальный Go-Live
1. В админ-панели Vercel перевести:
   ```env
   PAYMENT_GATEWAY_MODE="live"
   MOCK_PAYMENT_ENABLED="false"
   ```
2. Выполнить финальный `Redeploy` production-ветки.
3. Опубликовать проверенные товары каталога (`isPublished = true`).
4. Объявить официальный запуск интернет-магазина выкроек **LEKALO ZHIIDE**.
