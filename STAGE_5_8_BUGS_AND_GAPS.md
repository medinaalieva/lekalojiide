## 1. Классификация приоритетов

- **`P0 (Критический блокер передачи)`** — дефект, полностью препятствующий передаче проекта Адилету для наполнения каталога (делает невозможной работу админки, авторизацию, загрузку файлов или разрушает базу данных).
- **`P1 (Блокер коммерческого запуска)`** — дефект или отсутствующая интеграция, не мешающая наполнению каталога и тестированию, но обязательная для открытия реальных коммерческих продаж покупателям.
- **`P2 (Улучшение / Оптимизация)`** — некритические замечания по поддержке, CI/CD, документации или обновлению версий вспомогательных библиотек.

### GAP-01: Отсутствие производственных PDF-выкроек для 181 варианта
- **Приоритет:** **P1 (Блокер коммерческого запуска)**
- **Модуль:** Каталог товаров / Конструкторское бюро
- **Описание:**  
  В тестовой базе данных `lekalo_test` зарегистрировано 183 варианта для 23 товаров. Только 2 варианта («Пальто Чолпон» 42-A4 и 44-A4) содержат временные тестовые файлы, созданные на этапе разработки. 181 вариант не имеет прикрепленных файлов выкроек.
- **Влияние на передачу Адилету:** **Не блокирует.** Именно для наполнения этих 181 вариантов проект и передается Адилету.
- **Влияние на коммерческий запуск:** **Критическое.** Нельзя открывать платный доступ покупателям к товарам без файлов лекал.
- **Рекомендуемое действие:**  
  1. Передать конструктору выкроек стандарт качества Stage 5.2 и производственный трекер `STAGE_5_3_PDF_PRODUCTION_TRACKER.csv`.
  2. Адилету загрузить готовые пакеты PDF через форму Bulk Upload по каждому товару.

### GAP-02: Использование Mock-платежного шлюза
- **Приоритет:** **P1 (Блокер коммерческого запуска)**
- **Модуль:** `src/modules/payments/mock-payment.gateway.ts`, `payments.service.ts`
- **Описание:**  
  Платежный модуль архитектурно готов: поддерживает безопасную генерацию ссылок, верификацию HMAC-SHA256 подписей вебхуков, идемпотентность и автоматическое начисление прав `PurchaseEntitlement`. Однако в качестве провайдера подключен эмулятор `MockPaymentGateway`.
- **Влияние на передачу Адилету:** **Не блокирует.** Эмулятор позволяет Адилету безопасно тестировать сквозной путь покупки без списания реальных денег.
- **Влияние на коммерческий запуск:** **Критическое.** Для приема платежей в сомах (KGS) необходим реальный эквайринг (MBANK, O!Dengi, PayBox, DemirBank или Optima).
- **Рекомендуемое действие:**  
  1. Выбрать платежного партнера в Кыргызстане.
  2. Реализовать адаптер `IPaymentGateway` для выбранного API (по аналогии с `MockPaymentGateway`).
  3. Внести боевые ключи в `.env` Production.

### GAP-03: Отсутствие боевого SMTP-сервера для транзакционных писем
- **Приоритет:** **P1 (Блокер коммерческого запуска)**
- **Модуль:** `src/modules/auth/auth.service.ts`
- **Описание:**  
  Модуль сброса паролей генерирует криптографически стойкие одноразовые токены с SHA-256 хешированием. В тестовом окружении токен сброса пароля выводится в лог/ответ для обеспечения автоматизированного тестирования. В коде нет интеграции с реальным почтовым транспортом (Nodemailer / Resend / SendGrid).
- **Влияние на передачу Адилету:** **Не блокирует.** Администратор может авторизоваться и восстанавливать доступ тестовыми методами.
- **Влияние на коммерческий запуск:** **Высокое.** Покупатели должны получать ссылки на восстановление пароля и чеки заказов на свою электронную почту.
- **Рекомендуемое действие:**  
  1. Подключить провайдер почты (например, Resend API или корпоративный SMTP `smtp.yandex.ru` / `smtp.gmail.com`).
  2. Создать почтовый сервис `EmailService` с HTML-шаблонами писем (ссылка на сброс пароля, подтверждение заказа).

### GAP-04: Защита витрины от заказа выкроек без прикрепленных файлов
- **Приоритет:** **P1 (Блокер коммерческого запуска)**
- **Модуль:** `frontend/src/app/catalog/[slug]/ProductDetailView.tsx`
- **Описание:**  
  В настоящее время публичная карточка товара позволяет выбрать любой существующий в БД вариант и добавить его в корзину. Если для выбранного варианта конструктор еще не загрузил PDF-файл (`digitalFiles.length === 0`), заказ будет успешно создан и оплачен, но при попытке скачать файл в кабинете покупатель получит ошибку 404 «Файл выкройки готовится к публикации».
- **Влияние на передачу Адилету:** **Не блокирует.** Адилет видит реальную матрицу вариантов для каждого товара.
- **Влияние на коммерческий запуск:** **Высокое (риск жалоб покупателей).**
- **Рекомендуемое действие:**  
  В карточке товара на фронтенде добавить визуальный индикатор готовности лекала: если у варианта нет прикрепленного файла, отображать бейдж «Предзаказ / Файл в подготовке» или блокировать кнопку «В корзину» с подсказкой.

### GAP-05: Интерактивная браузерная автоматизация (DevToolsActivePort)
- **Приоритет:** **P2 (Улучшение)**
- **Модуль:** Тестовая инфраструктура / Playwright
- **Описание:**  
  При попытке запуска браузерного субагента для живого управления Chrome драйвер возвращает ошибку `Could not find DevToolsActivePort for chrome`, так как на машине запущен штатный пользовательский браузер без флага отладки.
- **Влияние на передачу Адилету:** **Не влияет.** Все функции проверены через прямой live HTTP API и модульные тесты (146 тестов).
- **Рекомендуемое действие:**  
  Настроить запуск headless Chrome в изолированном контейнере или в GitHub Actions CI.

---

### GAP-06: Предупреждение AWS SDK v3 о версии Node.js
- **Приоритет:** **P2 (Улучшение)**
- **Модуль:** `package.json`, окружение Node.js
- **Описание:**  
  AWS SDK v3 выводит предупреждение: `NodeVersionSupportWarning: The AWS SDK for JavaScript (v3) versions published after the first week of January 2027 will require node >=22. You are running node v18.12.1.`
- **Влияние на проект:** **Не влияет в настоящее время.** Система полностью совместима и работоспособна.
- **Рекомендуемое действие:**  
  При плановом обновлении инфраструктуры обновить Node.js до LTS-версии (Node 20 или 22).
