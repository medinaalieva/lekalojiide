## 2. Обращение с секретами и конфиденциальными данными

> [!CAUTION]
> **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:**  
> Передавать секретные ключи, пароли и конфигурационные строки подключения через незащищенные каналы связи:  
> **Открытый чат Telegram, WhatsApp, Viber, Skype, незашифрованная электронная почта.**

### Перечень критических секретов проекта:
1. `DATABASE_URL` — строка подключения к PostgreSQL, содержащая логин и пароль владельца базы. Утечка позволяет злоумышленнику полностью выкачать или уничтожить базу данных.
2. `JWT_SECRET` и `JWT_REFRESH_SECRET` — криптографические ключи, используемые сервером для подписи токенов авторизации пользователей. Утечка позволяет злоумышленнику сгенерировать токен любого администратора без знания пароля.
3. `SUPABASE_SERVICE_ROLE_KEY` / `S3_SECRET_ACCESS_KEY` — суперпользовательский ключ к объектному хранилищу. Утечка даёт прямой доступ к скачиванию всех платных лекал ателье.
4. `PAYMENT_SECRET_KEY` / `MERCHANT_SECRET` — секретный ключ проверки подлинности банковских вебхуков. Утечка позволяет злоумышленнику подделывать сигнатуры успешных платежей и бесплатно активировать заказы.
5. Пароли от почтовых ящиков SMTP (`SMTP_PASS`).

### Как безопасно передавать секреты:
- Использовать защищенные менеджеры паролей: **Bitwarden**, **1Password**, **KeePass**.
- Использовать сервисы одноразовых зашифрованных самоуничтожающихся записок (например: **OneTimeSecret**, **PrivateBin** с парольной защитой).

## 3. Почему НЕЛЬЗЯ использовать боевую среду (Production) для тестов

1. **Риск финансовых списаний:** Любая попытка тестовой покупки на боевом сервере приведёт к реальной транзакции с банковской карты и комиссии эквайера.
2. **Искажение бухгалтерской отчетности:** Тестовые фейковые заказы попадают в общую базу продаж, искажая расчет выручки, среднего чека и налогооблагаемой базы.
3. **Риск потери коммерческих данных:** Случайный запуск тестового скрипта очистки данных на боевой базе удалит реальные заказы настоящих клиентов.
4. **Уведомления реальным людям:** При тестировании с боевого сервера почтовые сообщения с чеками и ссылками могут случайно уйти реальным покупателям.
5. **Правило:** Все эксперименты, проверки нового кода и функционала проводятся **строго в тестовой среде (`lekalo_test`)** на локальном стенде разработчика.

## 4. Почему НЕЛЬЗЯ изменять конфигурационные файлы (`.env`) без согласования

Файлы `.env` связывают между собой все изолированные подсистемы платформы:
- **Опечатка в `DATABASE_URL`** $\rightarrow$ Сервер Fastify не сможет подключиться к пулу соединений и немедленно упадет при запуске (`Process exited with code 1`).
- **Смена `JWT_SECRET` на работающем сервере** $\rightarrow$ Все ранее выданные токены мгновенно станут недействительными, и 100% активных покупателей и администраторов выбросит из личных кабинетов.
- **Опечатка в адресах `CORS`** $\rightarrow$ Браузер заблокирует все клиентские запросы к API с ошибкой `Blocked by CORS policy`, витрина магазина перестанет отображать товары и корзину.
- **Правило:** Любое изменение переменных окружения на сервере согласуется с ведущим разработчиком и сопровождается созданием контрольной точки бэкапа.

## 5. Запрет на самостоятельный запуск миграций БД

> [!WARNING]
> **ОПАСНОСТЬ АВТОМАТИЧЕСКИХ МИГРАЦИЙ (`prisma db push`, `migrate dev`):**  
> При прямом выполнении команды `prisma db push` в боевой базе данных Prisma может принять решение об удалении колонок или пересоздании таблиц (`DROP TABLE`), если схема в локальном коде немного отличается от продакшена. Это приведёт к **безвозвратной потере данных**.

### Регламент внесения изменений в структуру БД:
1. Запрещено использовать `prisma db push` на боевой базе.
2. Любые изменения структуры таблиц оформляются исключительно в виде **чистых, проверенных SQL-файлов** (как файл `prisma/migrations/manual_password_reset_tokens.sql`).
3. Перед запуском любого SQL-скрипта в консоли Neon обязательно создается моментальный снимок (Snapshot / Point-in-Time Recovery).
4. Запрос выполняется администратором БД в транзакции `BEGIN ... COMMIT` с предварительной проверкой `SELECT current_database()`.

## 6. Безопасность облачного хранилища (Supabase S3)

Интернет-магазин выкроек продаёт интеллектуальную собственность. Защита файлов лекал от нелегального скачивания — приоритет №1.

### 6.1. Разделение бакетов
1. **Бакет `product-images`:**
   - **Статус:** `Public: true`.
   - **Назначение:** Фотографии товаров, миниатюры, баннеры.
   - **Доступ:** Прямой публичный доступ через CDN для быстрой загрузки страниц каталога в браузере.
2. **Бакет `pattern-files`:**
   - **Статус:** `Public: false` (СТРОГО ЗАКРЫТЫЙ / ПРИВАТНЫЙ).
   - **Назначение:** Файлы выкроек в формате PDF.
   - **Доступ:** Прямой доступ из интернета **полностью заблокирован**. Получить файл можно **только через временную подписанную ссылку (Presigned URL)**, сгенерированную бэкендом после строгой проверки, что покупатель действительно оплатил этот вариант.

### 6.2. Срок жизни ссылок (TTL)
- Временная ссылка на скачивание имеет ограниченный срок действия: **300 секунд (5 минут)**.
- Если покупатель передаст ссылку третьему лицу или попытается скачать файл через 10 минут, облако Supabase вернет ошибку `403 Access Denied` (срок действия подписи истек).
- Для законного покупателя это не создает проблем: в личном кабинете при нажатии кнопки «Скачать» сервер мгновенно генерирует свежую ссылку на следующие 5 минут.
