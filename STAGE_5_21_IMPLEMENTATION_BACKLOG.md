## 2. Спецификация задач P0 (Критический приоритет)

### TASK-P0.1: Автоматическая генерация варианта `ALL` при включении опции комплекта
- **Проблема**: Если у товара включен чекбокс `hasBundleOption = true` и задан `bundlePrice`, но при генерации матрицы не был выбран размер `ALL`, на витрине переключатель комплекта отображается, но нажатие «В корзину» падает с ошибкой `activeVariant = undefined`.
- **Решение**:
  1. В `CatalogService.batchGenerateVariants`: если `product.hasBundleOption === true`, автоматически создавать связку вариантов для размера `ALL` для каждого выбранного формата (например, `ALL / 164-170 / A4` и `ALL / 164-170 / PLOTTER_900`).
  2. В `ProductDetailView.tsx`: добавить защитную проверку — если у товара нет варианта `ALL`, блокировать кнопку покупки комплекта с понятной подсказкой «Комплект временно формируется».
- **Критерии приемки (DoD)**:
  - При создании товара с `hasBundleOption = true` варианты `ALL` генерируются автоматически.
  - Покупка комплекта на витрине добавляет вариант `ALL` с ценой `bundlePrice` без ошибок.

---

### TASK-P0.2: Контроль целостности цен форматов печати
- **Проблема**: Если для плоттера и А4 будут установлены разные цены через `priceOverride`, сервер обязан проверять, что клиент в корзине не подменил `variantId` А4 на Плоттер с сохранением меньшей цены.
- **Решение**: Серверный расчет корзины в `CartService` уже берет цену строго из базы данных (`variant.priceOverride ?? variant.product.basePrice`). Требуется покрыть тестом сценарий попытки модификации цены формата на клиенте.
- **Критерии приемки (DoD)**:
  - Unit/E2E тест подтверждает, что принудительный client override цены отклоняется.

## 3. Спецификация задач P1 (Обязательное ТЗ)

### TASK-P1.1: Загрузка инструкций по пошиву через админ-панель
- **Слои**: API (`StorageAdminController`), Frontend (`[id]/files/page.tsx`).
- **Спецификация API**:
  - `POST /api/v1/admin/storage/upload-instruction`:
    - Принимает `productId`, `title`, `fileBase64` или `url`.
    - Валидирует PDF, размер ($\le 30\text{ MB}$), считает SHA-256 чексумму.
    - Загружает в приватный бакет `instructions/`.
    - Создает запись в таблице `product_instructions`.
  - `DELETE /api/v1/admin/storage/instructions/:instructionId`: удаление/деактивация.
- **Спецификация UI**:
  - В `/admin/products/[id]/files` добавить третью вкладку: «Инструкция по пошиву».
  - Показать статус наличия инструкции, номер версии, размер файла, дату загрузки и кнопку тестового скачивания.
- **Критерии приемки (DoD)**:
  - Адилет загружает файл `Instruktsiya_Palto_Cholpon.pdf` с компьютера.
  - В карточке товара статус `hasInstruction` становится `true`.
  - После тестовой покупки инструкция появляется в кабинете покупателя и скачивается.
